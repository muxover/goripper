# GoRipper v0.0.4-pre — Garble/Obfuscation Detection & Stripped Binary Resilience

**Release date:** 2026-03-07

### Install

```bash
go install github.com/muxover/goripper/cmd/goripper@v0.0.4-pre
```

---

## Summary

Adds obfuscation and garble detection, heuristic function re-labeling for high-score binaries, string decryptor stub detection with XOR key recovery, stripped binary resilience via PE `.pdata` fallback, and CGo boundary mapping.

---

## What's included

### Obfuscation scoring

A new `internal/obfuscation` package computes a 0.0–1.0 score for every binary using four independent signals:

| Signal | Weight | Detail |
|--------|--------|--------|
| Shannon entropy of function names | 35% | Garble base-62 names score ≈ 3.5+ bits/char vs. normal ≈ 2–3 |
| Known-prefix ratio | 30% | < 10% `main.` / `runtime.` / `fmt.` etc. → likely garbled |
| String density | 20% | < 0.05 strings/function → strings likely encrypted |
| Build info absent | 15% | `debug/buildinfo` failure is a strong obfuscation signal |

Score → level: `none` (< 0.15) · `low` (0.15–0.34) · `medium` (0.35–0.59) · `high` (≥ 0.60)

### Heuristic function re-labeling

When `ObfuscationScore > 0.5`, garbled functions receive advisory tags based on their call targets:

| Tag | Trigger |
|-----|---------|
| `[suspected:network_connect]` | calls `net.Dial`, `net.(*Dialer)`, `syscall.Connect` |
| `[suspected:file_write]` | calls `os.Create`, `os.(*File).Write` |
| `[suspected:exec]` | calls `os/exec.(*Cmd).Run`, `syscall.Exec` |
| `[suspected:encryption]` | calls `crypto/aes.*`, `crypto/rc4.*`, `golang.org/x/crypto/*` |
| `[suspected:goroutine_spawn]` | calls `runtime.newproc` |
| `[suspected:http_client]` | calls `net/http.(*Client).Do` |
| `[suspected:registry_access]` | calls `golang.org/x/sys/windows/registry.*` |
| `[suspected:large_unknown]` | size > 4096 bytes, no recognisable calls |

### String decryptor stub detection

Garble can encrypt string literals behind small XOR stubs. GoRipper now detects these: functions with size < 100 bytes called by ≥ 50 other functions are flagged. XOR key recovery scans the stub body for `XOR AL, imm8` / `XOR r/m8, imm8` / `XOR r/m32, imm8` patterns.

```json
"decryptor_stubs": [
  {"name": "aB3xK9mP", "addr": "0x4a1234", "caller_count": 312, "xor_key": "0x3f"}
]
```

### Stripped binary resilience

When gopclntab is absent or fails to parse, the analyzer records a `Warning` and falls back to scanning the PE `.pdata` exception table to recover `(address, size)` pairs and generates synthetic names: `sub_0x4a1000`, `sub_0x4a1100`, … `function_source: "synthetic"` in JSON; `[SYNTHETIC]` marker in text output.

### CGo boundary mapping

Go functions that directly call CGo bridge functions are now identified. `SummaryOutput.CgoCallSites` lists Go function names that cross into CGo. `=== CGo Boundaries ===` section in text output when CGo is present.

### New output fields

| Field | Location | Description |
|-------|----------|-------------|
| `obfuscation_score` | `BinaryInfo` | 0.0–1.0 |
| `obfuscation_level` | `BinaryInfo` | none/low/medium/high |
| `obfuscation_indicators` | `BinaryInfo` | Human-readable reasons |
| `function_source` | `FunctionOutput` | `"pclntab"` / `"symbol_table"` / `"synthetic"` |
| `warnings` | `AnalysisResult` | Non-fatal pipeline issues |
| `decryptor_stubs` | `AnalysisResult` | String decryptor stubs |
| `cgo_functions` | `SummaryOutput` | Count of CGo bridge functions |
| `synthetic_functions` | `SummaryOutput` | Count of synthetic `sub_0x*` functions |
| `cgo_call_sites` | `SummaryOutput` | Go functions that call into CGo |
| `decryptor_stubs` | `SummaryOutput` | Count of detected decryptor stubs |
