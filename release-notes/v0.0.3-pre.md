# GoRipper v0.0.3-pre — LEA Length Inference, URL Splitting & First Test Suite

**Release date:** 2026-03-03

### Install

```bash
go install github.com/muxover/goripper/cmd/goripper@v0.0.3-pre
```

---

## Summary

This release ships two complementary string-quality fixes: LEA-guided strings now attempt
to infer their exact length from nearby instructions, and a new post-classification pass
splits any remaining URL blobs that contain multiple embedded URLs (the CMOVNE compiler
pattern). The result: consecutive hardcoded URLs — such as four Discord webhook URLs packed
back-to-back in `.rodata` — now appear as four clean individual strings instead of one
dirty 484-byte blob.

Also included: the first automated test suite (17 tests covering unit and integration paths)
and two small defensive fixes to type recovery and pclntab false-positive handling.

---

## What's included

### Fix 1 — LEA string length inference

**Before:** When `CrossReference()` found a LEA target not already in the header-pair scan,
it emitted a 512-byte printable run from that address. Adjacent string literals packed
without separators in `.rodata` were concatenated into one dirty blob.

**After:** The scanner now records the byte position of each LEA instruction. In the second
pass it decodes up to 15 instructions forward looking for a `MOV reg, <imm>` where the
immediate falls in `[minStringLen, 4096]`. When found, that value is used as the exact
string length. Otherwise it falls back to the 512-byte run.

```asm
LEA RAX, [RIP+offset]   ; string pointer
MOV RCX, 42             ; string length  ← now detected
```

### Fix 1b — Concatenated URL splitting (CMOVNE residual)

**Problem:** When four Discord webhook URLs are stored consecutively in `.rodata` without
separators and the Go compiler uses a CMOVNE conditional select, `findLengthNearby()` fires
the 512-byte fallback and emits a 484-byte blob containing all four URLs.

**Fix:** `SplitConcatenatedURLs()` runs as a post-classification pass after `Classify()`.
Any URL-typed string that starts with `https?://` and contains at least one additional
`https?://` at a non-zero position is split at each URL boundary. Each component inherits
the parent's `ReferencedBy` list.

### Fix 1c — URL classifier overhaul

**Problem:** `classifyOne()` used `strings.Contains(s, "://")` as a fallback, causing any
512-byte blob that happened to contain `://` somewhere in its bytes to be classified as URL.

**Fix:**
1. Remove the `://` Contains fallback entirely. The URL type now only matches strings that **start** with a URI scheme.
2. Generalise `reURL` from `https?|ftp|ws|wss` to the RFC 3986 pattern `[a-z][a-z0-9+\-.]*://` — any valid URI scheme is now recognised (mongodb, redis, git, ssh, ldap, …).

### Fix 2 — LEA-guided extraction (commit 633d054)

`CrossReference()` now emits strings that have no `(ptr, len)` header pair in `.rodata`
but are referenced by LEA instructions in `.text`, enabling extraction of hardcoded URLs
passed directly to HTTP clients.

### Fix 3 — Type recovery returns empty slice

`Recover()` in `internal/types/recovery.go` now returns `[]RecoveredType{}` instead of
`nil` when no types are found, making callers safe to range over the result.

### Fix 4 — pclntab nfunc sanity check

`ScanForPclntab()` and `FindGopclntab()` now require `nfunc > 10` in addition to the
existing 8-byte header validation, filtering out random data that accidentally matches the
magic bytes but has an implausible function count.

## Tests

First automated test suite — 17 tests across 4 files.

| File | Tests |
|------|-------|
| `internal/strings/extractor_test.go` | Empty input, header-pair extraction, min-length filter, non-printable filter, deduplication, out-of-range pointer |
| `internal/strings/classifier_test.go` | URL, IP, path, secret, pkgpath, plain; `SplitConcatenatedURLs` splits blob + passes single through |
| `internal/gopclntab/parser_test.go` | Parse pclntab from test binary; assert >100 functions, non-empty GoVersion |
| `pkg/analyzer/analyzer_test.go` | Full pipeline on test binary; assert TotalFunctions > 0, TotalStrings > 0 |

## Known limitations (carried forward)

- **CMOVNE plain blobs** — stdlib error-message strings still produce 512-byte plain blobs when `findLengthNearby()` cannot resolve their lengths. Fix in `v0.0.5-pre`.
- **ELF not integration-tested on Linux** — run `go test ./...` on a Linux machine for ELF coverage.
- **x86_64 only** — ARM64 support planned for `v0.2.0`.
