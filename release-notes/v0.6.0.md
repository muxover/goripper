# GoRipper v0.6.0 — Dynamic tracing and runtime analysis

**Release date:** 2026-05-30

### Install

```bash
go install github.com/muxover/goripper/cmd/goripper@v0.6.0
```

Or download a prebuilt binary from the [releases page](https://github.com/muxover/goripper/releases/tag/v0.6.0).

---

## Summary

GoRipper can now trace a binary as it runs, capturing function calls, syscalls, network connections, and file access as a structured JSONL event stream. Feeding that stream back into `analyze` annotates every function with actual call counts and hot-path flags — bridging static and dynamic analysis in one tool.

## What's included

### `goripper trace` command

```bash
# Trace for 10 seconds — human-readable table
goripper trace ./malware --timeout 10s

# Stream events as JSONL
goripper trace ./malware --jsonl -o trace.jsonl

# Trace + static analysis merged in one shot
goripper trace ./malware --analyze --jsonl

# Print hot path after tracing
goripper trace ./malware --hot-path

# Pass arguments to the traced binary
goripper trace ./server -- --port 8080
```

Event format:

```json
{ "type": "call",    "func": "main.dialServer", "addr": "0x401000", "ts_ns": 1234567890 }
{ "type": "return",  "func": "main.dialServer", "addr": "0x401000", "ts_ns": 1234567910, "duration_ns": 20 }
{ "type": "syscall", "name": "connect",         "args": ["AF_INET:192.168.1.1:4444"], "ts_ns": 1234567900 }
{ "type": "file",    "op": "open",              "path": "/etc/passwd", "ts_ns": 1234567950 }
{ "type": "net",     "op": "connect",           "net_addr": "192.168.1.1:4444", "proto": "tcp", "ts_ns": 1234567960 }
```

### Platform backends

**Linux** — tracefs uprobe interface. Writes uprobe entries to `/sys/kernel/debug/tracing/uprobe_events` and reads from `trace_pipe`. No CGo, no external dependencies. Requires `CAP_BPF` or root, kernel 5.8+.

**macOS** — generates a dtrace D script from the pclntab function list and runs it as a subprocess. Requires SIP disabled for dtrace or root.

**Windows** — Windows Debug API: `CreateProcess` with `DEBUG_PROCESS`, software INT3 breakpoints at every user function entry, single-step restore via trap flag in the thread CONTEXT. No elevated privileges required, works on Windows 10+.

### Static + dynamic merging

```bash
# Capture a trace first
goripper trace ./malware --jsonl -o trace.jsonl

# Merge into full static analysis
goripper analyze ./malware --trace-data trace.jsonl --json
```

Merging populates:
- `FunctionOutput.call_count` — times the function was actually called
- `FunctionOutput.total_time_ns` — total wall time spent in the function
- `FunctionOutput.is_hot` — `true` for top 10% by call count
- `AnalysisResult.observed_network_addrs` — actual IPs/hosts connected to
- `AnalysisResult.observed_file_paths` — actual file paths accessed
- `AnalysisResult.observed_syscalls` — syscalls actually invoked

Functions with `call_count == 0` were never executed — often the most interesting code.

### Hot path analysis

```bash
goripper trace ./malware --hot-path
```

```
main.main (100%)
  └── main.processRequests (94%)
        ├── main.parseRequest (41%)
        │     └── encoding/json.Unmarshal (38%)
        └── main.handleRequest (53%)
              └── main.callExternalAPI (51%)
```

### Flags

| Flag | Command | Description |
|------|---------|-------------|
| `--timeout duration` | `trace` | Stop after this duration (default: 30s) |
| `--jsonl` | `trace` | Stream events as JSONL |
| `--analyze` | `trace` | Merge trace with static analysis and emit result |
| `--hot-path` | `trace` | Print hot path tree after tracing |
| `--trace-data <file>` | `analyze` | Merge a saved JSONL trace into the analysis |
| `goripper trace <binary>` | — | New subcommand |
