# GoRipper v0.7.0 — Decompile to C (Experimental IR Foundation)

**Release date:** 2026-06-21

### Install

```bash
go install github.com/muxover/goripper/cmd/goripper@v0.7.0
```

Or download a prebuilt binary from the [releases page](https://github.com/muxover/goripper/releases/tag/v0.7.0).

---

## Summary

v0.7.0 ships the decompilation pipeline as an **experimental foundation**. `goripper decompile` lifts user-defined functions through a three-address IR, SSA renaming, variable recovery, and C type propagation, emitting `.c` skeletons per package. Output is structural — not yet readable source. String constant resolution, control flow reconstruction (if/else/while), and Go runtime pattern recognition are planned for v0.8.0.

## What's included

### `goripper decompile` command

```
goripper decompile <binary> [-o out/] [--max-funcs N] [-v]
```

Lifts all user-defined functions to C. Output layout:

```
out/
  main.c        — user package "main"
  net_http.c    — package "net/http" (sanitized)
  structs.h     — GoString, GoSlice, GoIface, _type, error
  stubs.h       — extern declarations for all called external functions
```

Functions that cannot be CFG-built (stripped, tiny thunks) emit a single `/* could not lift */` comment stub so the file always compiles to a consistent skeleton.

### IR lifter (`internal/ir`)

Three-address IR covers both x86_64 and ARM64 Go binaries:

- **x86_64**: MOV/LEA/ADD/SUB/IMUL/AND/OR/XOR/SHL/SHR/SAR/NEG/NOT/PUSH/POP/XCHG/CMP/TEST/CALL/RET/Jcc + SIMD variants. CMP+Jcc pairs are fused into `OpIf` with a condition expression (`==`, `!=`, `<`, `>`, …). Unknown opcodes fall back to Intel-syntax comments.
- **ARM64**: LDR/STR/LDP/STP/MOV/ADD/SUB/MUL/DIV/AND/ORR/EOR/LSL/LSR/ASR/NEG/CMP/CMN/TST/CBZ/CBNZ/BL/BLR/RET/B.cond. CBZ/CBNZ embed the zero-comparison directly in `OpIf`.

### SSA renaming (`internal/ir`)

Block-level single-assignment renaming: every write to a register variable (`_rax`, `_r0`, …) creates a versioned name (`_rax_v0`, `_rax_v1`). At multi-predecessor block entries, phi-like assignments carry the version from the single predecessor.

### Variable recovery (`internal/ir`)

After SSA: first-version parameter-register names become `param0`/`param1`/…, small-constant increment patterns become `i`/`j`/`k`, and remaining SSA variables become `v0`/`v1`/….

### Type propagation (`internal/ir`)

Forward type assignment from known Go runtime signatures (`runtime.newobject` → `void*`, `runtime.makeslice` → `void*`, `fmt.Println` params → `GoIface`, etc.) plus heuristics: loads are `void*`, arithmetic is `int64_t`. All unresolved variables default to `int64_t`.

### Flags

| Flag | Default | Description |
|------|---------|-------------|
| `-o`, `--output <dir>` | `out` | Output directory for `.c` files |
| `-v`, `--verbose` | `false` | Log progress every 100 functions |
| `--max-funcs N` | `0` | Limit functions decompiled (0 = all) |
