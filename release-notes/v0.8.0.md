# GoRipper v0.8.0 — Go Source Reconstruction

**Release date:** 2026-07-02

### Install

```bash
go install github.com/muxover/goripper/cmd/goripper@v0.8.0
```

Or download a prebuilt binary from the [releases page](https://github.com/muxover/goripper/releases/tag/v0.8.0).

---

## Summary

v0.8.0 adds Go source reconstruction to the decompile pipeline. `goripper decompile --lang go` emits a compilable Go module from a binary — one subdirectory per user package, with runtime calls lifted to Go idioms and stub bodies so `go build ./...` succeeds. The existing `--lang c` output is unchanged.

---

## What's included

### `--lang go` output mode

```
goripper decompile <binary> --lang go [-o out/]
```

Output layout:

```
out/
  go.mod              — module recovered; go 1.21
  main/
    main.go           — recovered main package functions
    stubs.go          — stub bodies for unresolved external calls
  net/http/
    http.go           — recovered net/http package functions
    stubs.go          — stub bodies for unresolved external calls
```

`go build ./...` in the output directory compiles without errors. Stub functions panic on call; replace them to test recovered logic.

### Runtime pattern lifting

14 `runtime.*` calls are lifted to Go source idioms instead of being emitted as opaque function calls:

| Runtime call | Go output |
|---|---|
| `runtime.gopanic` | `panic(v)` |
| `runtime.gorecover` | `recover()` |
| `runtime.newproc` | `go func() { _ = fn }()` |
| `runtime.deferproc`, `runtime.deferprocStack` | `defer func() { _ = fn }()` |
| `runtime.deferreturn` | *(suppressed — implicit in Go)* |
| `runtime.chansend1` | `ch <- v` |
| `runtime.chanrecv1` | `v = <-ch` |
| `runtime.makeslice` | `make([]byte, len, cap)` |
| `runtime.makemap` | `make(map[any]any)` |
| `runtime.makechan` | `make(chan any, size)` |
| `runtime.convT2I`, `runtime.convT64`, `runtime.convTstring` | `any(v)` |

### Go type mapping

C typeprop types are mapped to their Go equivalents in the emitted source:

| C type | Go type |
|---|---|
| `int64_t` | `int64` |
| `uint64_t` | `uint64` |
| `int32_t` | `int32` |
| `uint32_t` | `uint32` |
| `void*`, `*_type` | `unsafe.Pointer` |
| `GoString` | `string` |
| `GoSlice` | `[]byte` |
| `GoIface` | `any` |
| `error` | `error` |

### Compiler-error suppression

Reconstructed SSA output has structural properties that would normally fail `go build`. These are handled automatically:

- **Unused variables**: `var (v0 int64; ...)` + `_ = []any{v0, ...}` suppresses errors for SSA vars not read on all paths.
- **Unused import**: `var _ unsafe.Pointer` keeps the `unsafe` import active in every package file.
- **Unused labels**: `collectReferencedLabels` emits only labels that are targets of a `goto` or branch.
- **Keyword collisions**: `init` → `_init`; all Go keywords prefixed with `_`.
- **Duplicate names**: functions sharing the same short name within a package are suffixed `_1`, `_2`, etc.
- **Missing `main`**: the `main` package always gets `func main() {}` if no `main` function was recovered.

### Flags

| Flag | Default | Description |
|------|---------|-------------|
| `--lang` | `c` | `c` for C skeletons (unchanged); `go` for compilable Go module |
| `-o`, `--output <dir>` | `out` | Output directory |
| `--max-funcs N` | `0` | Limit functions decompiled (0 = all) |
| `-v`, `--verbose` | `false` | Log progress every 100 functions |
