# GoRipper v0.6.5 — Correctness and output fixes

**Release date:** 2026-06-19

### Install

```
go install github.com/muxover/goripper/cmd/goripper@v0.6.5
```

Or download a pre-built binary from the [releases page](https://github.com/muxover/goripper/releases/tag/v0.6.5).

---

## Summary

v0.6.5 is a bug-fix release with no new features. It corrects eleven issues found during deep quality review after v0.6.0 shipped — covering function classification accuracy, trace output correctness, scan-dir behavior on Windows, and versioned script exports.

---

## Fixed

- **Function package extraction — generics**: `slices.Sort[go.shape.string]` yielded package `"slices.breakPatternsCmpFunc[go.shape"` due to the `[...]` suffix confusing dot-parsing. Generic type-parameter suffixes are now stripped before any dot is examined.
- **Function package extraction — method entries**: pclntab method entries like `hash.Hash.Size` yielded package `"hash.Hash"` instead of `"hash"`, misclassifying stdlib interface methods as user functions. Dotted names with no slash are now reduced to their root component.
- **Function package extraction — module path methods**: `internal/abi.Kind.String` yielded `"internal/abi.Kind"` instead of `"internal/abi"`. TypeName suffixes after the last `/` in a module path are now stripped.
- **`internal/*` classified as stdlib instead of runtime**: `runtimePrefixes` contained `"internal/"` (trailing slash), causing `HasPrefix` checks against `"internal//"` to never match. Changed to `"internal"` — `internal/abi`, `internal/cpu`, `internal/bytealg`, and all similar packages now count as runtime, not stdlib.
- **Obfuscation false positives**: `FindDecryptorStubs` counted stdlib and runtime functions toward the high-fan-in decryptor heuristic, producing false positives on normal binaries. Now restricted to user-defined functions only.
- **Threat classifier accuracy**: ransomware detection relied on string-pattern scanning for file extensions; keylogger and miner detection used raw string patterns. All three now require explicit behavior tags (`FILE_READ`+`FILE_WRITE`+`CRYPTO`+obfuscation score for ransomware, `KEYLOG` for keylogger, `MINER` for miner) produced by the behavior tagger — eliminating false positives from benign binaries that happen to mention `.docx` or a mining-related string.
- **`trace --analyze` output mixing**: the raw events table or JSONL stream was written to the output destination before the merged analysis result, producing a mixed stream. Events are now consumed silently when `--analyze` is active; only the analysis result is written.
- **`trace --analyze --jsonl` not emitting JSONL**: the merged analysis was written as pretty-printed JSON. Now calls `output.WriteJSONL` for proper newline-delimited records.
- **`scan-dir` analyzing non-executables on Windows**: `isExecutable` returned `true` for every regular file (source files, READMEs, etc.), causing silent failed analysis attempts on each one. Now reads the first 4 bytes and only accepts PE (`MZ`) or ELF (`\x7fELF`) magic.
- **Hardcoded `v0.4.0` in script exports**: IDA, Ghidra, and YARA outputs always claimed to be generated by GoRipper v0.4.0. Now uses `version.Version` injected at build time via ldflags.
- **Windows tracer ASLR**: `trace` on Windows did not account for ASLR — breakpoints were placed at the binary's preferred image base addresses, not the actual runtime addresses. The tracer now reads `lpBaseOfImage` from the `CREATE_PROCESS_DEBUG_EVENT` and applies the slide to all function addresses.
