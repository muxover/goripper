# GoRipper v0.2.0 — ARM64, Mach-O, disasm abstraction, struct fields, itab recovery

**Release date:** 2026-04-28

### Install

```bash
go install github.com/muxover/goripper/cmd/goripper@v0.2.0
```

Or download a prebuilt binary from the [releases page](https://github.com/muxover/goripper/releases/tag/v0.2.0).

---

## Summary

Architecture milestone. GoRipper now supports ARM64 and Mach-O in addition to x86_64 PE and ELF. A new arch-neutral `Disassembler` interface replaces direct x86asm usage throughout the call graph, CFG builder, and string cross-referencer — all three stages now work correctly on both architectures. Type recovery is deeper: struct fields are fully extracted, and a new itab pass recovers which concrete types implement which interfaces.

---

## What's included

### ARM64 support

Full ARM64 disassembly via a new `internal/disasm` package. All analysis stages that previously used `golang.org/x/arch/x86/x86asm` directly now go through a `Disassembler` interface with separate x86_64 and ARM64 backends.

ARM64 instruction classes handled:

| Instruction | Op |
|-------------|-----|
| `BL target` | `OpCall` (direct) |
| `BLR Xn` | `OpCall` (indirect) |
| `RET` | `OpRet` |
| `B target` | `OpUncondBranch` |
| `B.cond target` | `OpCondBranch` |
| `BR Xn` | `OpUncondBranch` (indirect) |
| `CBZ`, `CBNZ`, `TBZ`, `TBNZ` | `OpCondBranch` |
| `ADRP` + `ADD` pair | `OpAddrLoad` (full VA resolved) |
| `ADR target` | `OpAddrLoad` |

`ADRP`+`ADD` pairs are decoded as a single `OpAddrLoad` with the fully resolved data address in `AddrRef` — equivalent to x86 `LEA RAX, [RIP+disp]`.

### Mach-O support

GoRipper opens macOS Mach-O binaries including fat/universal archives. `binary.Open()` now auto-detects all Mach-O magic variants (32-bit, 64-bit, fat — both endiannesses). Fat binaries prefer the amd64 slice; arm64 is the fallback.

Section names are translated automatically so all callers use canonical names:

| Canonical name | Mach-O name |
|----------------|-------------|
| `.text` | `__text` |
| `.rodata` | `__rodata` / `__const` |
| `.gopclntab` | `__gopclntab` |
| `.typelinks` | `__typelinks` |
| `.itablink` | `__itablink` |
| `.data` | `__data` |

`FindGopclntab()` checks `__gopclntab` first, then falls back to scanning `__text` / `__rodata` / `__data` for pclntab magic.

### Real arch detection

ELF and PE loaders previously hardcoded `"x86_64"` for `Arch()`. They now read the actual architecture from the binary header (`e_machine` for ELF, `Machine` for PE). This is what selects the correct disassembler backend.

| File | Field | Values handled |
|------|-------|----------------|
| ELF | `e_machine` | `EM_X86_64`, `EM_AARCH64`, `EM_ARM`, `EM_386` |
| PE | `Machine` | `AMD64`, `ARM64`, `ARMNT`, `I386` |

### Struct field recovery

When `--types` is enabled, struct rtype descriptors are now fully parsed. The `structType` layout following the 48-byte rtype header is walked to extract each field's name, type, and byte offset from the start of the struct. These appear in `RecoveredType.Fields` and in the text report:

```
type http.Request struct {
    Method          string  // offset=0
    URL             *url.URL  // offset=16
    Proto           string  // offset=24
    ...
}
```

### Interface implementation recovery

GoRipper reads the `.itablink` section (present in ELF and Mach-O, PE equivalent is `.itablink`) to produce a list of every concrete type that implements an interface:

```json
"interfaces": [
  { "interface": "io.Reader",   "concrete": "*bytes.Buffer", "itab_addr": "0x5c3a20" },
  { "interface": "http.Handler","concrete": "main.myHandler","itab_addr": "0x5c3b40" }
]
```

The text report shows an `=== Interface Implementations ===` section when `--types` is used and bindings are found.

## Fixed

- `Arch()` on ELF and PE loaders no longer hardcodes `"x86_64"` — this caused the ARM64 disassembler to never be selected even when an ARM64 binary was opened.
